= Qualify a Governed VM Inference Fleet

Virtualization + AI 401 operated one bounded VM change. This 75–90 minutes
level-501 lab asks
a different question: can a three-VM service path stay inside a declared SLO,
capacity, containment, and evidence envelope?

The qualification adapter evaluates supplied measurements. It does not migrate,
disrupt, certify, promote, or call a model. Every bundled measurement is a
`REHEARSAL` fixture, not a production benchmark or Intel performance claim.

== Show

A change advisory board needs one correlated answer across VM identity,
placement, inference, telemetry, migration, disruption, and state continuity.

== Learn

Follow `DISCOVER → BASELINE → MIGRATE → DISRUPT → CORRELATE → QUALIFY → HANDOFF`.
The adapter can return `ALLOW_REVIEW`, `REFUSE`, or `ABSTAIN`; a human owns
promotion.

== Do

[source,bash,role="execute"]
----
export LAB_NAMESPACE="$(oc project -q)"
export QUAL_URL="http://virtualization-ai-501-qualification-adapter:8080"
export PRESENTATION_URL="http://virtualization-ai-501-presentation:8080"
export FIXTURE_ROOT="$PRESENTATION_URL/fixtures"
printf 'namespace=%s\nadapter=%s\n' "$LAB_NAMESPACE" "$QUAL_URL"
----

The terminal uses the namespace-local presentation Service for fixture retrieval.
For the interactive presentation, use the embedded *Story* tab; this Service URL
is not a link to open from your laptop. No TLS verification bypass is required.

== Prove

[source,bash,role="execute"]
----
curl -fsS "$QUAL_URL/healthz" | jq '{status,mode,authority}'
----

The expected mode is `REHEARSAL` and the authority is
`HUMAN_PROMOTION_REQUIRED`.
